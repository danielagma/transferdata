Feature: Multi "Parent" Orders Display in Order Blotter (DWU-596)
  As a trader
  I want to view the child orders linked to my submitted multi order
  So that I can understand how the execution is progressing

  Background:
    Given the Darwin UI Order Blotter is open
    And the user has submitted a "MULTI" order that generated multiple child orders

  # Covers Requirement 3, 6, 7 and "Order Linking ID" mapping
  Scenario: Hierarchical grouping of Parent, Child, and Fill records
    When the multi order is displayed in the blotter widgets
    Then a single "Parent" order record is displayed at the top level
    And the "Source (NEW)" column for the Parent displays "MULTI"
    And all derived "Child" orders are correctly grouped under the Parent record
    And the "Order Linking ID" of the Child orders matches the "Internal Order ID" of the Parent
    And the fills of the Child orders are correctly grouped under their respective Child records

  # Covers Requirement 5 and Excel dynamic rollups (Quantity & Price)
  Scenario: Dynamic calculation of Parent order quantities and prices (VWAP)
    Given the Child orders receive partial executions (fills)
    When the blotter refreshes
    Then the Parent "Quantity Filled" equals the sum of the "Quantity Filled" of all Child orders
    And the Parent "Quantity Remaining" equals "Total Quantity" minus "Quantity Filled"
    And the Parent "Avg. Price" correctly calculates the Volume Weighted Average Price (VWAP) of the Child orders
    And the Parent "Create Time" remains unchanged (static)

  # Covers Excel logic for Venue, ISIN, and Instrument Name condensation
  Scenario: Dynamic condensation of Venue and ISIN on Parent level
    Given the multi order generated Child orders routed to multiple distinct venues
    And the Child orders cover multiple distinct ISINs
    When the Parent order details are evaluated
    Then the Parent "Venue" column displays "Multi"
    And the Parent "ISIN" column displays "Multi"
    And the Parent "Instrument Name" column is Empty
    # Alternate path
    When all Child orders are routed to a single ISIN
    Then the Parent "ISIN" displays the specific ISIN
    And the Parent "Instrument Name" displays the specific product description

  # Covers Excel logic for Order State and Fill Status
  Scenario: Lifecycle status aggregation on Parent level
    Given at least one Child order is in "Active" state
    And the Parent "Executed Quantity" is greater than zero but less than "Total Quantity"
    When the blotter displays the statuses
    Then the Parent "Order State" is "Active"
    And the Parent "Fill Status" is "Partial"
    
    When all Child orders transition to "Inactive" state
    And the Parent "Executed Quantity" equals "Total Quantity"
    Then the Parent "Order State" updates to "Inactive"
    And the Parent "Fill Status" updates to "Complete"

  # Covers Requirements 1, 2, 8
  Scenario: Child orders and direct-to-venue orders maintain BAU display logic
    Given a standard direct-to-venue order exists
    When comparing it to a Multi "Child" order
    Then the Child order "Cancel" and "Amend" logic remains BAU
    And all other BAU fields (Venue Order ID, Fill ID, etc.) behave identically to direct-to-venue orders
