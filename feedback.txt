Summary / Title:
[Bug] Validation error message incorrectly states "Must be smaller than 8" for out-of-bounds precision inputs

Description:
While testing the precision enhancement for the "View Defaults" screen (DWU-170), the system correctly blocks out-of-bounds or decimal values (e.g., 9.5). However, the validation error message text is logically incorrect. It displays "Must be smaller than 8."

According to AC1, the system must allow values from 0 up to 8. Therefore, 8 is a completely valid input. The current message implies that 8 is invalid.

Steps to Reproduce:

Navigate to Static > Bond Referential > View Defaults screen for any selected bond.

In the Column Format section, enter an out-of-bounds number or a decimal value (e.g., 9.5) in any precision field (e.g., Driver).

Click outside the field to trigger the validation.

Observe the red validation error text below the field.

Expected Result:
The system should block the invalid input and display an accurate error message, such as:

"Must be smaller than or equal to 8." OR

"Must be smaller than 9."

Actual Result:
The system displays the error message: "Must be smaller than 8.", which contradicts the accepted maximum limit of 8.

Environment:

DEV2

Severity / Priority:

Severity: Minor (The blocking logic works, but the UI text is misleading).

Priority: Medium / Low
